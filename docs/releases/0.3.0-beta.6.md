# Leanlet 0.3.0-beta.6

This candidate makes the capability manifest a toolable contract shared by
runtime registration, application code, CI, and editor/schema integrations.

## Added

- `validateLeanletManifest()` for side-effect-free validation of untrusted JSON.
- `parseLeanletManifest()` and `LeanletManifestValidationError` for throwing
  integration paths with structured issues.
- JSON Pointer paths and stable issue codes for automated tooling.
- Version 1 JSON Schema, a `leanlet-ai/manifest` entry, and a raw
  `leanlet-ai/manifest-schema` package export.
- `leanlet manifest validate <file>` and `leanlet manifest schema` commands.

## Changed

Kernel registration now uses the public manifest parser rather than a private
validator. Duplicate providers and duplicate asset paths are rejected because
they create ambiguous preference and release-planning behavior.

## Compatibility

The release is additive for manifests that already satisfy the documented
contract. Applications that repeated a provider or asset path must remove the
duplicate. Unknown manifest properties remain allowed and are ignored by the
runtime, preserving namespaced application annotations.

## Limits

Manifest validation does not load adapter code, verify downloaded bytes,
measure actual memory, establish browser support, or evaluate model quality.
Use asset planning, capability probes, browser integration tests, and
representative evaluation data for those separate release gates.
