# Leanlet 0.3.0-beta.5

This candidate adds browser capability discovery and ordered, inspectable
fallback routes for applications that ship more than one implementation of a
bounded task.

## Added

- `probeRuntimeCapabilities()` for a versioned, privacy-minimal profile of
  WebAssembly, Workers, SharedArrayBuffer, cross-origin isolation, WebGPU, and
  standardized WebGPU features.
- `matchesRuntimeRequirements()` for explaining whether a runtime profile
  satisfies a Leanlet implementation's requirements.
- `defineCapabilityRoute()` for ordered implementation selection with explicit
  continuation rules, shared cancellation/deadlines, and attempt provenance.
- Tests for unavailable and failing WebGPU probes, feature matching,
  incompatible candidates, explicit fallback, cancellation, and no-match
  behavior.

## Compatibility

The APIs are additive. Existing `defineLeanlet()`, `VisionLeanlet`, kernel,
flow, model-pack, and check integrations require no migration. Runtime
requirements belong to route candidates and do not change the manifest schema
in this prerelease.

## Behavioral contract

Fallback is never inferred from a failure. A candidate advances only when its
`continueOn` list explicitly includes the returned status. All incompatible
skips and executions are retained in `attempts`; the final result remains an
ordinary accepted, abstained, or failed `LeanletResult`.

## Limits

Capability probing establishes primitive availability, not model fitness,
accuracy, memory safety, sustained performance, or browser support guarantees.
Applications still need representative evaluation and user-visible failure
policy. The profile intentionally omits device and adapter identity.
